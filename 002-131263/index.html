00この資料は、作ったものと今後の運用方法をまとめたものである

2026年4月から6月にかけて構築した素材プラットフォームについて、

  • 何を作ったのか
  • いま何が動いているのか
  • 草木研に何が残るのか
  • これから誰が何をどう操作するのか

を一通りまとめた。技術の前提知識がなくても運用できる粒度で書いている。不明な点は遠慮なく聞いてほしい。

01作ったものは「素材を一か所に集め、そこから全部を動かす仕組み」である

構築の出発点にした考え方は、企画時から一貫して次のものだった。

素材情報を一度登録すれば、産直便の商品ページにも、法人向けカタログにも、社内管理画面にも反映される。「素材」を中心に事業全体がドライブされるアーキテクチャ。

草木研の素材情報は、着手時点で Google ドライブ・Instagram・Excel のプライスリスト・古谷さんといくらさんの記憶に分散していた。同じ素材の情報が場所ごとに違い、どれが正しいか誰にも分からない状態だった。

そこで「素材の台帳」を一つ作り、そこを唯一の正とした。

この形にしたことが、今回の構築の中身のほとんどである。

03いま動いているものは四つある

#何か何のためのものか
①素材ストアサイト会員（飲食店・法人）が素材を見て注文する売り場
②素材・事例の編集画面スタッフが素材の情報と導入事例を追加・修正するための画面
③会員審査の仕組み申請者を Slack のボタン一つで承認し、Shopify のタグを自動で付ける
④台帳から Shopify への同期素材の台帳の内容を Shopify の商品として反映する

既存の nihonkusakilab.com（さんぽ直の売り場）には一切手を触れていない。同じ Shopify ストアの中で、売り場だけが二つ並んで動いている構造になっている。

04草木研に残るものは、システムより先にデータである

今回いちばん価値が高いのは、サイトやプログラムではなく、集めて整理したデータである。これは会社が変わっても、担当者が変わっても残る。

  • 素材マスター136ファイル — 産地・提供時期・価格・香り・味・合う食材・合わないもの・物語・文化的背景
  • 顧客376社・案件189件・導入事例9件・エピソード331件
  • Instagram 2アカウントの全アーカイブ — 投稿・ストーリーズ・ビジネスDMを、あとから検索できる形に整理したもの
  • イベント25件のナレッジ
  • 2026年プライスリストと送料モデル

サイトの見た目は作り直せる。集めたデータは作り直せない。

05自分たちでできることは、三つの入口に分かれる

日々の運用で必要になる操作は、次の三つの入口のどれかで完結する。

入口1：Shopify 管理画面 — 値段・在庫・販売時期を変える

Shopify の管理画面から、次のものが変更できる。反映はすぐ。

変えたいものどこを触るか
価格商品ページ → 価格
在庫の有無商品ページ → 在庫
商品名・商品説明商品ページ → タイトル・説明
商品写真商品ページ → メディア
販売シーズン（提供月）商品ページ下部「メタフィールド」→ season.available_months
「生」の提供月同 → season.available_months_fresh
予約受付の期間同 → booking.window_start / booking.window_end
会員の承認タグ顧客ページ → タグ

「メタフィールド」は、商品ページを下までスクロールすると出てくる追加項目の欄である。ここに入れた値がそのままサイトの表示になる。

7月25日の改修について

それまでは、管理画面で販売時期を直しても、次に開発側が同期をかけると元に戻ってしまう作りだった。いただいた「気軽に変更したい」というご要望はこの点にあったと理解している。現在は、管理画面で入れた値が優先され、同期をかけても巻き戻らない。気候変動で採取時期が毎年動くとのことだったので、シーズンごとに管理画面から直接変えられる。

入口2：素材・事例の編集画面 — 素材の中身と導入事例を足す

ブラウザで URL を開き、メールアドレスに届く確認コードを入れると使える。GitHub のアカウントなどは不要。

【URL・アクセス権は別途ご案内】

できることは次のとおり。

やりたいこと手順
素材の説明文・香り・キャッチコピーを直す素材一覧 → 該当素材 → 該当欄を編集 → 保存
導入事例を新しく追加する事例一覧 → 新規 → タイトル・本文・写真を入れる → 使われている素材を紐づける → 公開にする
事例の写真を足す・並べ替える・消す事例編集画面 → 写真欄。先頭の1枚が表紙になる
事例を非公開にする事例編集画面 → 状態を「非公開」に
素材と事例の紐づけを直す素材側からも事例側からも編集できる

事例を公開するには二つの条件がある。素材が1件以上紐づいていること、紐づけの確認済みチェックが入っていること。この二つが揃っていないと公開状態にできない。事例と素材がつながっていないと、素材ページから事例へたどれないためである。

保存すると数分でサイトに反映される。誰がいつ編集したかは自動で記録される。

価格と在庫はこの画面では編集しない。Shopify が正なので、そちらで変更する（入口1）。

入口3：Slack の会員審査 — 申請者を承認する

Slack で /kusaki-members と打つと、審査待ちの申請者が一覧で表示される。

  • 申請者ごとにカードが出る（区分・店名・ホームページ・担当者・利用目的つき）
  • 「承認」を押すと、Shopify に「Jテロワールユーザー」タグが自動で付く
  • 続けて既存の Shopify Flow が動き、「卸販売先」タグの付与と承認メールの送信が自動で走る
  • 誰がいつ承認したかは顧客メモに記録される

保留・却下のボタンもある。承認するかどうかの基準は、これまでと変わらない。

06自分たちでできないことは、外に頼む形になる

該当するもの

  • サイトに固定で使われている写真の差し替え（商品写真ではなく、ページの装飾として置かれているもの）
  • トップページのバナー
  • ページの文言・レイアウトの変更
  • 新しい機能の追加

頼むときに伝えること

外部の制作会社やエンジニアに依頼する場合、次の情報を先に伝えると話が早い。

項目内容
売り場の作りShopify Hydrogen（React Router 7 / TypeScript）
公開先Shopify Oxygen
編集画面・会員審査Cloudflare Workers
データの持ち方Markdown ファイル + git
Shopify ストアdev-yamabushi.myshopify.com

注意点を一つ

一般的な Shopify の制作会社では対応できない可能性が高い。Shopify のサイト制作は通常「Liquid」というテンプレート言語で行われるが、今回の素材ストアはそれとは別の Hydrogen という仕組みで作られている。Hydrogen を扱えるエンジニアは、Shopify の制作者全体の中では多くない。

これは今回の構築で採用した設計に起因するものなので、事前に伝えておく。「Shopify Hydrogen の開発経験があるか」を最初に確認するのが確実である。

07よくある質問

Q. サイトの写真を変えたいときは、どこを触ればいいのか。

商品の写真は Shopify 管理画面（入口1）。導入事例の写真は編集画面（入口2）。それ以外のページ装飾の写真は外部への依頼になる。

Q. 販売時期は本当に自分たちで変えられるのか。

Shopify 管理画面のメタフィールド欄から変えられる。7月25日の改修で、同期による巻き戻りが起きない構造になった。

Q. 事例集はどうやって足すのか。

編集画面（入口2）から追加する。素材の紐づけと確認チェックが公開の条件になる。

Q. 請求書払いと領収書のダウンロードはどうなるのか。

今回の構築範囲には含まれていない。実際の請求と入金確認の業務フロー（誰が発行し、いつ、どの締め日で確認しているか）と、使用中の領収書フォーマット、インボイス制度への対応要否が分かれば、実現方法の検討ができる。別件としてあらためて相談してほしい。

Q. 素材の台帳は誰が持っているのか。

データそのものは草木研の事業情報である。保管場所とアクセス方法については、引き渡しの中で個別に確認したい。
